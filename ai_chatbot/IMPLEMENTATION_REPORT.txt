CIVICHERO AI CHATBOT MODULE - IMPLEMENTATION REPORT
====================================================

PROJECT OVERVIEW
================
Implementation of the CivicHero AI Chatbot Module based on the technical architecture plan.
Consists of a Python FastAPI microservice handling RAG vector search and LLM orchestration,
coupled with an ASP.NET Core Web API (to be implemented in Phase 4) managing JWT auth,
user identity, RDS message persistence, and trusted context generation.

ARCHITECTURE COMPLIANCE
======================
✓ Main Backend: ASP.NET Core 8 Web API with AWS RDS MySQL (civicherodb) - Phase 4 pending
✓ AI Microservice: Python FastAPI running statelessly on port 8001 - COMPLETED
✓ Data Access Boundary: Python service does NOT connect directly to RDS - enforced
✓ Security: Internal microservice communication protected via X-Internal-Service-Key header
✓ No API keys exposed to React or logged - security measures implemented

TECHNOLOGY STACK
================
AI & RAG Stack:
- Embedding Provider: NVIDIA API using model nvidia/nv-embedqa-e5-v5
- Primary LLM: Groq API
- Fallback LLM: NVIDIA NIM API
- Final Fallback: Rule-based deterministic responder
- RAG Indexing: Local JSON embedding file (generated/embeddings.json) using Cosine Similarity
- RAG Defaults: Chunk size = 250 words, Overlap = 40 words, Top-K = 3, Min Similarity Score = 0.70

FEATURES IMPLEMENTED
====================
1. RAG Pipeline:
   - Text chunking with configurable overlap
   - NVIDIA embedding generation (nvidia/nv-embedqa-e5-v5)
   - Cosine similarity search
   - Configurable similarity threshold (0.70) and Top-K (3)

2. LLM Provider Abstraction:
   - Clean interface for swapping LLM providers
   - Groq primary provider (mixtral-8x7b-32768)
   - NVIDIA NIM fallback (nemotron-3-8b-chat)
   - Rule-based deterministic final fallback

3. Resilient Failover System:
   - Tries providers in order: Groq → NVIDIA → Rule-based
   - Handles API failures, rate limits, timeouts gracefully
   - Provides visibility into which provider was used

4. Security & Safety:
   - Input sanitization (HTML/script tag removal)
   - Prompt injection detection
   - Information extraction attempt detection
   - Secret/API key leakage prevention
   - Internal service key authentication (X-Internal-Service-Key header)

5. API Design:
   - RESTful endpoints with proper HTTP status codes
   - Request/response validation using Pydantic
   - Comprehensive OpenAPI documentation (/docs endpoint)
   - Health check endpoints for monitoring
   - Conversation tracking with UUIDs

6. Configuration Management:
   - Environment-based configuration via .env file
   - Separation of concerns (config, logging, providers)
   - Easy parameter tuning (chunk size, overlap, similarity threshold)

USAGE INSTRUCTIONS
==================
1. Environment Setup:
   - Copy .env.example to .env
   - Fill in required values:
     * NVIDIA_API_KEY=your_nvidia_api_key
     * GROQ_API_KEY=your_groq_api_key
     * (Optional) NVIDIA_CHAT_MODEL, GROQ_MODEL, etc.

2. Build Knowledge Base:
   ```bash
   python -m app.rag.index_builder
   ```
   This generates ./generated/embeddings.json

3. Start the Service:
   ```bash
   python -m app.main
   ```
   Server will be available at http://localhost:8001

4. API Endpoints:
   - GET /health - Basic health check
   - GET /health/ready - Readiness check
   - GET /health/live - Liveness check
   - POST /api/v1/chat/generate - Main chat endpoint
     Required header: X-Internal-Service-Key: your_internal_key
     Body: {
       "message": "User question",
       "conversation_id": "optional_uuid",
       "user_id": "optional_user_id",
       "include_context": true
     }
